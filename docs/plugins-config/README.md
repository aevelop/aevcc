# Plugins and Marketplaces

Source of truth (regenerated by `scripts/export.sh`):

- [marketplaces.txt](marketplaces.txt) -- `name source` (19)
- [plugins.txt](plugins.txt) -- `plugin@marketplace version [disabled]` (44 installed: 27 enabled, 17 `disabled`;
  `latest` = marketplace had no version tag)

## Install

```bash
bash scripts/install/15-cursor-plugins.sh    # builds the local aevcc-local marketplace (see Notes)
bash scripts/install/20-plugins.sh
```

Manual, one at a time (same commands work inside Claude Code as `/plugin ...`):

```bash
claude plugin marketplace add anthropics/claude-plugins-official           # one per line of marketplaces.txt
claude plugin install superpowers@claude-plugins-official --scope user -y  # one per line of plugins.txt
claude plugin disable impeccable@impeccable --scope user                   # only for lines ending in "disabled"
```

Turn a disabled one on later: `claude plugin enable <plugin@marketplace>` (or `/plugin` -> Installed).

## Verify

```bash
claude plugin list
jq '[.enabledPlugins[]] | {installed: length, enabled: map(select(.)) | length}' ~/.claude/settings.json   # 44 / 27
```

## Notes

- `superpowers` is obra's project, installed from the official marketplace (newer). The older duplicate from
  `superpowers-marketplace` was uninstalled 2026-08; that marketplace stays registered for `double-shot-latte`.
- `ecc` marketplace: this machine now tracks upstream `affaan-m/ECC`; until 2026-09 it was the fork `twebdevemt/ecc`.
- Plugins ship their own hooks, MCP servers (context7, context-mode, supabase docs) and skills. Nothing extra to install.
- `typescript-lsp` / `php-lsp` need `typescript-language-server` / `intelephense` on PATH (step 00).
- `mattpocock-skills` 1.2.3 ([mattpocock/skills](https://github.com/mattpocock/skills), [aihero.dev/skills](https://www.aihero.dev/skills)) is
  the engineering workflow spine since 2026-10-02, replacing GSD: `/grill-with-docs` or `/grill-me` -> `/to-spec` ->
  `/to-tickets` -> `/implement` (drives `/tdd`, ends with `/code-review`); `/wayfinder` for big efforts,
  `/diagnosing-bugs`, `/improve-codebase-architecture`, `/ask-matt` as router, plus productivity skills (`/teach`,
  `/wait-what`, `/handoff`). Run `/setup-matt-pocock-skills` once per repo (writes `docs/agents/*.md`: issue tracker,
  triage labels, doc layout). The routing rule that makes it win over superpowers brainstorming and ecc flows lives
  in the global CLAUDE.md (step 10). Installed as the read-only official-marketplace plugin, so updates arrive
  automatically; the `npx skills` copy is the alternative for hacking on the skills, never both.
- `claude-code-setup` enabled 2026-10-02 (`/claude-code-setup:claude-automation-recommender` suggests hooks/skills for a repo).
- Disabled = installed but `false` in `settings.json` `enabledPlugins`: no skills, hooks or commands load until enabled.
- Files: `~/.claude/plugins/{installed_plugins.json,known_marketplaces.json,cache/}`.
- `watch` (`/watch <url> <question>`, [repo](https://github.com/bradautomates/claude-video)) lets Claude watch
  videos. Reference machine uses the Gemini engine only: the YouTube URL goes straight to Google, nothing is
  downloaded, Claude only gets the timestamped answer. It needs a free Google AI Studio key
  (<https://aistudio.google.com/apikey>) in `~/.config/watch/.env` as `GEMINI_API_KEY=...` (mode 0600; the skill
  reads it from there, not from the shell). Step 20 writes that file when `GEMINI_API_KEY` is exported before
  running it; otherwise create it by hand. Settings (engine, detail) persist in `~/.config/watch/`. The local
  engine (`--engine local`, frames + transcript read by Claude) additionally needs `yt-dlp` (`brew install yt-dlp`)
  and optionally WhisperX via the bundled `setup.py --install-whisperx`; not installed on the reference machine.
- `ponytail` ([repo](https://github.com/DietrichGebert/ponytail)) injects a "laziest senior dev" ruleset on every
  session (SessionStart hook) and into every subagent, pushing the model toward the smallest change that works.
  Levels `lite` / `full` / `ultra` / `off`; default `full`. Switch per session with `/ponytail <level>`, or for
  every session with `PONYTAIL_DEFAULT_MODE` or `defaultMode` in `~/.config/ponytail/config.json` (not created on
  the reference machine, so defaults apply). `/ponytail-review` returns a delete-list for the current diff,
  `/ponytail-audit` for the whole repo, `/ponytail-debt` collects deferred `ponytail:` shortcuts. Overlaps with the
  "Simplicity First" rules in the global CLAUDE.md; keep both, ponytail adds the review commands.
- `design` ([Anthropic knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins/tree/main/design),
  also listed in the Anthropic Directory as "Design") is the product-design workflow plugin: `/design:critique`,
  `/design:design-system`, `/design:handoff`, `/design:ux-copy`, `/design:accessibility`,
  `/design:research-synthesis` plus matching background skills (design-critique, design-handoff, ux-writing,
  accessibility-review, user-research, design-system-management). Works standalone from a screenshot, a
  description, or a page Claude just built; the `/design` canvas itself is the Claude Design artifact, not this
  plugin. Bundles HTTP MCP connectors (figma, slack, linear, asana, atlassian, notion, intercom) that appear as
  `plugin:design:*` in `claude mcp list` and stay inert until you OAuth via `/mcp`; the reference machine has
  authenticated none of them. Different from `frontend-design` (code generation) and the `designer-skills`
  plugins (disabled, skill libraries).
- `cursor-team-kit` and `thermos` ([cursor/plugins](https://github.com/cursor/plugins)) ship only Cursor
  manifests, so step 15 (`scripts/install/15-cursor-plugins.sh`, list in `PLUGINS`) builds them as Claude Code
  plugins in the local marketplace `aevcc-local` (`~/.claude/local-marketplace`), then installs them. It runs before
  step 20 so the marketplace exists; re-run it to update (version is `<upstream version>+<upstream sha>`; local
  plugins are read live from their folder, so changes apply at the next session start or `/reload-plugins`).
  Agent adaptations: Cursor's `model: fast` -> `haiku`, `is_background` dropped, built-in `subagent_type` `shell` /
  `explore` -> `general-purpose` / `Explore`, and bare plugin agent names -> `<plugin>:<agent>`.
  - `cursor-team-kit`: 18 skills (`/cursor-team-kit:deslop`, `fix-ci`, `loop-on-ci`, `review-and-ship`,
    `verify-this`, `what-did-i-get-done`, ...) and 2 agents (`ci-watcher`, `thermo-nuclear-code-quality-review`).
    Its 2 Cursor rules become `~/.claude/rules/no-inline-imports.md` (always on) and
    `~/.claude/rules/typescript-exhaustive-switch.md` (only for TS files via `paths`).
  - `thermos`: `/thermos:thermos` runs both reviewer agents in parallel and merges their findings;
    `/thermos:thermo-nuclear-review` (bugs, security, breaking changes) and
    `/thermos:thermo-nuclear-code-quality-review` run one pass. All three are slash-command only
    (`disable-model-invocation`). The code-quality skill is byte-identical to cursor-team-kit's copy.
- `pstack` needs no build step: the `cursor-plugins` marketplace (the cursor/plugins repo itself) publishes an
  official Claude Code build from `harness/pstack/claude-code`, installed by step 20 like any other plugin. 58 skills
  (`/pstack:poteto-mode`, `architect`, `swarm`, `tdd`, `unslop`, 27 `principle-*`, ...) and 2 agents
  (`pstack:poteto-agent`, `pstack:comment-sicko`); about 4.8k always-on tokens per session. Its
  `docs/harness/claude-code.md` maps Cursor tool, subagent and model names to Claude Code at runtime and skips
  Cursor-only steps (Automations, cloud agents). `/pstack:setup-pstack` writes per-role model choices to
  `~/.claude/rules/pstack-models.md`; not run on the reference machine, so skills use their default models.
  The marketplace also offers `origin-apps` (not installed).
- `impeccable` ([pbakaus/impeccable](https://github.com/pbakaus/impeccable), Apache-2.0) was installed disabled at
  1.3.0; enabled at 4.8.0 on 2026-10-29. 4.x is one skill with 24 verbs (`/impeccable polish`, `audit`, `critique`,
  `init`, `doctor`, `hooks off`, ...) and 4 agents. Workflow guide for 4.x:
  [impeccable-workflow.md](impeccable-workflow.md). It adds 3 user-wide hooks (SessionStart, PostToolUse on Edit/Write of
  design-relevant files incl. `.ts`/`.js`, Stop "design deep pass") that run a native engine binary, downloaded on
  first use from the repo's GitHub releases into `~/.impeccable/bin/` and checked against `engine-checksums.txt`.
  Hooks never block edits, they add reminders; `/impeccable hooks off` silences them per project. New designs fetch
  directions from impeccable.style; the anonymous "which direction was picked" record is off via
  `IMPECCABLE_NO_TELEMETRY=1` in settings `env` (step 50).
- `chrome-devtools-mcp` ([ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp),
  installed 2026-11-11) bundles the `chrome-devtools` MCP server (`npx chrome-devtools-mcp@1.13.0`, drives its own
  Chrome via Puppeteer: performance traces, network, console, DOM) and 8 skills (`chrome-devtools`,
  `chrome-devtools-cli`, `a11y-debugging`, `cookie-debugging`, `debug-optimize-lcp`, `memory-leak-debugging`,
  `inspect-in-devtools`, `troubleshooting`). Its 1.13.0 `plugin.json` declares `commands` as an array of objects,
  which Claude Code 2.1.322 rejects (`Validation errors: commands: Invalid input`), so step 20 deletes that key in
  the marketplace clone before installing. Nothing is lost: the one command only aliased the `inspect-in-devtools`
  skill. The clone is therefore dirty; if `claude plugin marketplace update chrome-devtools-plugins` fails, run
  `git -C ~/.claude/plugins/marketplaces/chrome-devtools-plugins checkout .claude-plugin/plugin.json`, update, and
  re-patch only if the install still fails. Third browser tool next to `claude-in-chrome` and `playwright`.
  Needs on the machine: Node with `npx` (step 00) and Google Chrome stable in `/Applications`. Nothing else to
  install up front: the first tool call downloads `chrome-devtools-mcp@1.13.0` through `npx` into the plugin data
  dir (needs network once) and launches its own Chrome with a separate profile. No API key or login. Tools show as
  `mcp__plugin_chrome-devtools-mcp_chrome-devtools__*` (33: navigation, input, snapshot/screenshot, console,
  network, performance traces, Lighthouse, heap snapshots); skills as `chrome-devtools-mcp:<skill>`.
